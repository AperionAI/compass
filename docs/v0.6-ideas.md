# Compass 0.6 — candidate features

Working list for the next minor. Written after 0.5 shipped (4 Sep 2026).
Nothing here is committed until it moves into `ROADMAP.md`.

Ground rules that still apply: offline, no telemetry, no tokio, no HTTP
client crate (rustls for TLS is fine), single `compass` binary. Compass
assesses. Smartflow enforces. If an idea needs a running gateway, it's
not a Compass idea.

Effort is a gut call: **S** = a day, **M** = a few days, **L** = a week+.

---

## Tier 1 — closes the CI loop we opened in 0.5

### `compass diff` (M)

`compass diff old.json new.json` prints what changed between two scored
reports: overall score, per-framework score, controls that flipped
verdict, evidence checks that went from pass to fail. Markdown and JSON
output. This is the PR comment people actually want: "score 73 → 78,
`art_12_traceability` regressed to fail." Reuses the existing JSON
renderer as the input format, so no new schema.

### Baseline gate: `compass report --baseline compass-baseline.json` (S)

Fail CI only if the score drops below a committed baseline, not a fixed
`--threshold`. A ratchet. Teams at 55/100 can still adopt it on day one
without a red build, and it stops them backsliding. Add
`--update-baseline` to write the new baseline when they improve.

### GitHub Action (S, separate repo)

`AperionAI/compass-action`. Installs the release binary, runs `report`
with `junit,sarif`, uploads the SARIF to code scanning, attaches the
HTML as an artifact, posts the `diff` as a PR comment. The pieces all
exist in 0.5; the action is the glue. Most of the "how do I use this"
questions go away.

### `compass badge` (S)

Writes a shields.io-style SVG of the overall score and framework list
for a README. Local file, no network. Cheap, and it's how people find
out a repo is scored at all.

## Tier 2 — evidence quality

### Evidence freshness (S)

Every evidence file gets a `captured_at` (from the last record timestamp
or file mtime). `doctor` and the report flag anything older than N days
(default 90) as **stale**. A green control backed by a chain from last
year isn't green. Configurable per framework in the assessment file.

### Document attachments with hashes (M)

`compass ingest --doc risk-register.pdf --for art_9_risk_system`. Compass
records the path and SHA-256, and the control shows "document attached,
hash verified" without parsing the PDF. Attest bundles include the
hashes so an auditor can check they got the same file. Already in the
"later" bucket; worth pulling forward because Annex IV documentation is
what most teams are being asked for right now.

### More ingest adapters (S each)

There's a playbook for Azure OpenAI and LangSmith in `docs/evidence/`
but no `--from` adapter for either. Add `--from azure-openai`,
`--from langsmith`, `--from anthropic`, `--from vertex`. The generic
adapter shape in `src/adapters/` already fits.

### `compass record` improvements (M total)

- **Anthropic Messages API shape.** Record already detects
  `anthropic` in the upstream host, but only parses the OpenAI
  completions/chat shape properly. Parse `/v1/messages` and its SSE
  events so Claude traffic produces full evidence, not just an opaque
  body.
- **`--redact bodies`.** Store request/response hashes and metadata
  only, not the text. Legal will ask for this the first time someone
  points `record` at production traffic with customer data in it. The
  chain still verifies; logging-completeness still scores.
- **`--upstream-ca <pem>`.** Add a corporate root to the rustls store.
  Removes the "corporate MITM fails" limitation without touching the
  default webpki trust.
- **Risk tier on record.** Tag each recorded call with the T1/T2/T3
  tier from `action_risk.rs` at capture time, so the action-risk
  coverage check works on recorded traffic without a second pass.

## Tier 3 — explainability and trust

### `compass explain <control_id>` (S)

Prints the control text, its effective date, the evidence rule that
feeds it, what the current verdict is and exactly why (which file,
which check, which threshold). Same idea as Shield's `--explain`.
Cuts most "why is this red" questions.

### `compass doctor --json` and `compass frameworks --json` (S)

Machine-readable gap list so a dashboard or a script can consume it.
Trivial, and people have asked.

### Attestation counter-signing (M)

`compass attest sign --bundle x.json --signing-key ...` adds a second
Ed25519 signature to an existing bundle without changing the payload.
`verify` reports every signer. Lets a compliance officer counter-sign
the engineer's attestation. Still offline, still one primitive.

### Attestation expiry (S)

`--valid-for 90d` writes `not_after` into the payload. `verify` fails
past that date. An attestation from 2025 shouldn't verify green in
2027 without saying so.

## Tier 4 — bigger swings

### Portfolio roll-up (M)

`compass report --assessment sys-a.yaml --assessment sys-b.yaml`. One
report across many AI systems. EU registration is per system; boards
want one number. Per-system table plus an org score, with the worst
control per system called out.

### Assessment schema versioning + `compass migrate` (S)

Stamp `schema_version` in `compass-assessment.yaml`. When a catalog
renames or splits a control, `migrate` rewrites the file instead of
silently dropping answers. We already dodged this once by keeping
`art_79_incident_reporting` as the id; next time we won't get lucky.

### ISO/IEC 42001 catalog (L)

Management-system controls, so it maps onto the QMS and change
management questions we already ask. Third catalog after NIST. Only
worth it if NIST lands first and the crosswalk holds up.

### Editable `serve` mode (M)

Answer the questionnaire in the browser dashboard and write back to
the YAML. Right now `serve` is read-only with a re-scan button. Most
non-engineers will only ever use this path.

### Shell completions and man page (S)

`compass completions zsh|bash|fish`. clap already generates them; we
just don't wire them into the Homebrew formula.
